# SCHOOL BRAWL CUP

Полноценный сайт школьного турнира: главная страница, регистрация команды из трёх игроков, публичный список подтверждённых команд и закрытая панель организатора.

## Что внутри

- `index.html` — главная страница и последние опубликованные команды.
- `register.html` — регистрация капитаном команды и необязательного запасного.
- `teams.html` — публичный каталог команд, поиск и фильтр по классам.
- `admin.html` — закрытая панель организатора.
- `css/style.css` — адаптивный дизайн.
- `js/` — клиентская логика страниц.
- `netlify/functions/` — серверные функции: настройки, список команд, приём заявок и администрирование.
- `database/schema.sql` — схема Supabase, ограничения доступа и антиспам-лимит.

## Архитектура и безопасность

Сайт размещается на Netlify, данные хранятся в Supabase PostgreSQL, вход организатора выполняется через Supabase Auth.

Ключ `SUPABASE_SERVICE_ROLE_KEY` используется только внутри Netlify Functions. Он не включён в HTML или браузерный JavaScript. В браузер передаётся только публичный `SUPABASE_ANON_KEY`. Таблицы закрыты Row Level Security; публичные страницы получают список через серверную функцию, которая возвращает только подтверждённые и опубликованные команды.

Администратор допускается одновременно по двум условиям: успешный вход через Supabase Auth и совпадение email с `ADMIN_EMAIL` на сервере. Самостоятельной регистрации администраторов на сайте нет.

Контактные данные не собираются. Публичная карточка содержит только название команды, игровые ники и классы. Администратор отдельно включает публикацию каждой подтверждённой заявки.

## 1. Создать базу данных Supabase

1. Создайте проект на [supabase.com](https://supabase.com/).
2. Откройте **SQL Editor → New query**.
3. Скопируйте весь файл `database/schema.sql`, вставьте в редактор и нажмите **Run**.
4. В **Project Settings → API** скопируйте:
   - Project URL;
   - `anon` / publishable key;
   - legacy `service_role` JWT key из раздела Legacy API Keys. Для этого проекта используйте именно legacy-ключ: код отправляет его как Bearer token к PostgREST.
5. В **Authentication → Providers** убедитесь, что включён Email/Password.
6. В **Authentication → Settings** отключите публичную регистрацию пользователей (расположение переключателя зависит от интерфейса Supabase). Организатора создайте вручную через **Authentication → Users → Add user**. Укажите email и пароль. Не создавайте учётные записи для участников турнира.

> Важно: не публикуйте `service_role` / secret key, не отправляйте его участникам и не вставляйте его в файлы из `js/`.

## 2. Настроить переменные окружения

Для локального запуска создайте в корне проекта файл `.env`:

```env
SUPABASE_URL=https://YOUR-PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SERVICE_ROLE_KEY
ADMIN_EMAIL=organizer@example.com
```

Замените значения своими. `ADMIN_EMAIL` должен в точности соответствовать email созданного пользователя Supabase (регистр не важен). Файл `.env` исключён из Git через `.gitignore`; не добавляйте его в публичный архив и не отправляйте в репозиторий.

## 3. Открыть проект локально

Нужен установленный Node.js 18 или новее и Netlify CLI.

```bash
npm install -g netlify-cli
npm run check
npm test
netlify dev
```

Netlify CLI запустит сайт вместе с функциями; обычно локальный адрес будет показан в терминале (часто `http://localhost:8888`). Открывайте именно адрес Netlify Dev, а не `index.html` напрямую: прямое открытие файла не запускает серверные функции.

Для локального запуска Netlify Dev должен получить переменные из `.env`. Если ваша версия CLI не подхватывает файл автоматически, задайте те же четыре переменные в окружении терминала перед `netlify dev`.

## 4. Проверить регистрацию

1. Убедитесь, что в Supabase выполнен SQL из `database/schema.sql`.
2. Запустите `netlify dev` и откройте страницу `/register.html`.
3. Отправьте тестовую заявку с тремя игроками.
4. В Supabase → **Table Editor → teams** проверьте, что запись появилась со статусом `pending` и `is_public = false`.
5. Откройте `/admin.html`, войдите с учётной записью организатора, подтвердите команду и нажмите **«Опубликовать на сайте»**.
6. Проверьте `/teams.html` и главную страницу. Команда должна появиться в списке.
7. Снимите публикацию или удалите тестовую заявку, когда проверка завершена.

## 5. Опубликовать на Netlify

1. Создайте аккаунт на [netlify.com](https://www.netlify.com/).
2. Рекомендуемый способ — загрузить проект в приватный Git-репозиторий и выбрать **Add new site → Import an existing project**. Не добавляйте в репозиторий файл `.env`.
3. Если не хотите использовать Git, установите Netlify CLI и выполните `netlify login`, затем `netlify init` из корня проекта. Для проекта с серверными функциями используйте CLI (`netlify deploy --prod`) или Git-развёртывание, а не обычную загрузку только статических файлов через Drop.
4. Параметры уже описаны в `netlify.toml`: каталог публикации — корень проекта, функции — `netlify/functions`.
5. В настройках сайта откройте **Environment variables** и добавьте `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` и `ADMIN_EMAIL`.
6. Запустите новое развёртывание (**Deploys → Trigger deploy → Deploy site**), чтобы функции получили переменные окружения.
7. Откройте выданную Netlify ссылку. Её можно переименовать в настройках домена сайта, если свободно желаемое имя.

Если используете Git, отправляйте только файлы проекта без `.env`. Переменные вводятся только в Netlify UI.

## 6. Панель организатора

Откройте `https://ВАШ-САЙТ.netlify.app/admin.html` и войдите email/паролем Supabase пользователя, чей email задан в `ADMIN_EMAIL`.

В панели доступны:

- просмотр всех заявок, включая ожидающие и отклонённые;
- подтверждение или отклонение заявки;
- редактирование названия, ников и классов;
- удаление заявки;
- отдельная публикация/скрытие подтверждённой команды;
- открытие и закрытие регистрации;
- поиск и фильтр по статусу.

После обновления страницы нужно войти заново: токен панели хранится только в памяти вкладки. Пароль на стороне сайта не сохраняется.

## 7. Что работает и что требует настройки

| Возможность | Состояние |
|---|---|
| Адаптивные главная, регистрация, участники и админ-страницы | Реализовано |
| Проверка обязательных полей и запасного игрока | Реализовано на клиенте и сервере |
| Приём заявок и постоянное хранение в Supabase | Реализовано; нужны Supabase-проект, SQL и переменные Netlify |
| Несколько одновременных отправок | Поддерживается PostgreSQL и серверными функциями |
| Публичный список только подтверждённых и опубликованных команд | Реализовано |
| Защищённая панель и проверка email администратора на сервере | Реализовано; нужно создать пользователя Supabase и задать `ADMIN_EMAIL` |
| Открытие/закрытие регистрации | Реализовано |
| Антиспам | Honeypot, проверка полей, уникальный токен отправки и лимит 3 попытки с одного IP-хеша за 10 минут |
| Проверка на настоящем Netlify/Supabase с данными школы | Не выполнена в этом архиве: для неё нужны ваши ключи и развёрнутый проект |

## Важные примечания

- Регистрация по умолчанию открыта после первого выполнения SQL. Организатор может закрыть её в панели.
- Новые заявки всегда получают статус `pending` и не публикуются автоматически.
- Публично показываются игровые ники и классы только после подтверждения и отдельной публикации организатором.
- Rate limit использует хеш IP, а не хранит исходный IP-адрес. Счётчик ограничивает три попытки на один хеш за десятиминутное окно.
- Для реального школьного турнира согласуйте сбор и публикацию ников/классов с ответственным взрослым или администрацией школы. Не добавляйте в форму телефоны, адреса и другие лишние персональные сведения.
